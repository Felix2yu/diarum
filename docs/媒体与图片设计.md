# 媒体与图片设计

> 适用范围：日记正文插图、媒体库、回收站、缩略图与灯箱。本文描述当前实现（截至 `45fbb0d`），
> 涉及后端 `internal/store`、`internal/api`、`internal/imaging` 与前端 `web/src/lib`、`web/src/routes/media`。

---

## 一、能力总览

| 能力 | 实现要点 |
| :--- | :--- |
| 上传入口 | 文件选择 / 拖拽入编辑区 / 粘贴截图，三者共用上传队列 |
| 上传体验 | 并发 3、进度、取消、重试、失败回滚占位符 |
| 存储后端 | 本地目录（默认）、S3 兼容对象存储、Chevereto 外链 |
| 缩略图 | 预设 `thumb` / `medium` 与自定义 `?thumb=WxH`，按需生成并落盘缓存 |
| 日记关联 | 保存日记时解析正文媒体 URL，写入 `diary_images`，不依赖上传时的手工关联 |
| 回收站 | 软删除 → 恢复 → 永久删除；保留 30 天，后台每日自动清理 |
| 未引用清理 | 列出没有被任何日记正文引用的媒体，支持一键全部移入回收站 |
| 灯箱 | 全局单例，支持键盘、滚轮/双击/双指缩放、拖动平移、移动端滑动切换与下拉关闭 |

## 二、数据模型

### 2.1 `media` 表

| 字段 | 说明 |
| :--- | :--- |
| `id` | 主键，`r` + 14 位十六进制 |
| `file` | 存储文件名（经 `SafeFilename` 处理） |
| `name` | 展示名，默认取原始文件名 |
| `alt` | 无障碍描述 |
| `owner` | 所属用户 |
| `created` / `updated` | 时间戳（`YYYY-MM-DD HH:MM:SS.mmmZ`） |
| `deleted_at` | 非空表示在回收站中，存放移入时间 |
| `diary` | **历史遗留列**，已不参与读写；关联以 `diary_images` 为准 |

### 2.2 `diary_images` 表（迁移 v9）

```sql
CREATE TABLE diary_images (
    diary_id TEXT NOT NULL,
    media_id TEXT NOT NULL,
    created  TEXT NOT NULL,
    PRIMARY KEY (diary_id, media_id),
    FOREIGN KEY(diary_id) REFERENCES diaries(id) ON DELETE CASCADE,
    FOREIGN KEY(media_id) REFERENCES media(id) ON DELETE CASCADE
);
CREATE INDEX idx_diary_images_media ON diary_images(media_id);
```

- 语义：**“这条日记的正文里出现了这张图”**，与媒体是否在回收站无关。
- 双向级联：删除日记或永久删除媒体都会自动清理关联（`PRAGMA foreign_keys = ON`，`DeleteMedia` 另有显式兜底）。
- `created` 为关联建立时间，用于媒体详情里日记的顺序。

### 2.3 关联推导规则

- 从正文中匹配 `/api/v1/files/media/<mediaId>/<filename>`（正则 `([A-Za-z0-9]+)`），按首次出现顺序去重。
- 只关联**同一 owner** 的媒体与日记，跨用户引用直接忽略。
- 保存路径：`UpsertDiaryWithSession`（新增/更新，且仅正文变化时）、`UpdateDiaryByID`、
  `BatchUpdateDiaries`（事务内）、`InsertImportedDiary`、`RestoreDiaryVersion`。
- 元数据类保存（只改心情/天气/标签）不会触发同步，因此不会误删关联。
- 软删除媒体时保留关联：日记正文仍然引用它；恢复后无需重新保存日记。

### 2.4 升级回填

迁移 v9 执行 `backfillDiaryImages`，幂等，来源有两处：

1. 旧的 `media.diary` JSON（历史手工关联）；
2. 所有日记正文中的媒体 URL。

legacy `data.db` 迁移的场景下，复制完成后会再次回填（`createSchema` 阶段新库还没有数据）。

## 三、存储与访问

### 3.1 上传后端

由用户设置 `image_upload.provider` 决定，缺省 `local`（兼容旧的 `chevereto.enabled` 开关）：

| provider | 行为 |
| :--- | :--- |
| `local` | 写入 `data/storage/media/<mediaId>/<file>`；用户可用 `image_upload.local.path` 覆盖目录（相对路径基于 `data/`） |
| `s3` | 写入 `image_upload.s3.*` 配置的 bucket，key 为 `media/<id>/<file>` |
| `chevereto` | 前端直传外部图床，**不落库**，仅把外链 URL 写入正文 |

### 3.2 文件读取

- `GET /api/v1/files/media/:id/:filename`，鉴权支持 `Authorization: Bearer` 或 `?token=`（`<img>` 无法带请求头）。
- 前端只在渲染时拼接 token（`getMediaDisplayUrl`），**正文里永远不写 token**，避免泄漏与失效。
- 原图响应 `Cache-Control: private, max-age=3600`。

### 3.3 变体缓存

- 目录：`data/cache/media-variants/<mediaId>/<variant>.<jpg|png>`，首次请求生成，命中后 7 天缓存。
- 写缓存使用临时文件 + rename，失败不影响本次响应。
- 永久删除媒体时连带删除该目录。

## 四、上传链路

### 4.1 前端校验与队列

- 类型：`image/jpeg`、`image/png`、`image/gif`、`image/webp`（历史 SVG 仍在上传前端的允许列表，服务端会拒绝）。
- 大小：单文件 50MB。
- 队列（`web/src/lib/utils/uploadQueue.ts`）：默认并发 3，状态 `queued / uploading / success / error / canceled`，
  支持 `retry`、`cancel`（AbortController）、`remove`、`clearCompleted`。
- 占位符：入队时在光标处插入 `![上传中：<文件名>](uploading:<jobId>)`；
  成功替换为正式 Markdown，失败/取消回滚占位符并提示。

### 4.2 三个入口

| 入口 | 触发 | 说明 |
| :--- | :--- | :--- |
| 文件选择 | 工具栏按钮 / `MediaPicker` | `multiple`，一次可多选 |
| 拖拽 | 整个编辑区 | 拖入显示“松开以上传图片”遮罩，仅接受文件类型为 `Files` 的拖拽 |
| 粘贴 | 编辑区 textarea | 剪贴板含图片时拦截默认行为，直接入队（不粘成文件名/base64） |

### 4.3 服务端校验

- 读取前 512 字节做 `http.DetectContentType` 嗅探，只允许 JPEG / PNG / GIF / WebP；
  SVG（`text/xml`、`application/xml`）一律拒绝，避免内联脚本导致存储型 XSS。
- `header.Size > 50MB` 拒绝。
- 上传接口**不再接收 `diary` 字段**，也不创建空日记；上传只负责“把文件存下来”。

## 五、缩略图与变体

`internal/imaging`：

| 参数 | 结果 |
| :--- | :--- |
| `?variant=thumb` | 最长边 400，质量 82 |
| `?variant=medium` | 最长边 1200，质量 85 |
| `?thumb=300x300` | 自定义尺寸，单边钳制在 16–1600 |
| `?thumb=300x300` | 媒体库卡片缩略图 |
| `?thumb=200x200` | 编辑器内媒体选择器（`MediaPicker`） |

- 等比缩放（`scaleWithin`），不裁剪；按 EXIF 方向先旋转再缩放。
- 解码失败（如历史 GIF/SVG）直接回退原图，不返回 500。
- 前端 `getMediaFileUrl(media, thumb)` / `getMediaDisplayUrl(media, thumb)` 统一拼装。

## 六、回收站、未引用与自动清理

### 6.1 回收站

- 软删除：`DELETE /api/v1/media/:id` → 写 `deleted_at`，文件保留。
- 恢复：`POST /api/v1/media/:id/restore` → 清空 `deleted_at`。
- 永久删除：`DELETE /api/v1/media/:id/permanent` → 删文件 + 删行（关联级联）+ 删变体缓存。
- 清空：`DELETE /api/v1/media/trash` 逐条永久删除，返回成功/失败数。

### 6.2 自动清理

- 保留期固定 **30 天**（`store.MediaTrashRetention`）。
- `PurgeExpiredTrashedMedia` 按 `deleted_at <= 截止时间` 永久删除，单个失败仅记日志。
- 调度：`cmd/diarum/main.go` 的 `startMediaTrashPurge`，启动执行一次 + 每 24 小时一次，逐用户执行。

### 6.3 未引用媒体

- 定义：`deleted_at = ''` 且 `diary_images` 中不存在该媒体。
- 典型来源：上传后没有保存正文、正文里删掉了图片、导入遗留文件。
- `DELETE /api/v1/media/unreferenced` 一次性把全部未引用媒体移入回收站（不是永久删除），
  仍可在回收站确认或恢复。

## 七、API 一览

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| GET | `/api/v1/media` | 媒体库分页（`page`、`perPage`，按创建时间倒序） |
| GET | `/api/v1/media/:id` | 单条媒体，`diary` 字段为关联日记 ID 列表 |
| POST | `/api/v1/media` | 上传（`file` / `name` / `alt`） |
| DELETE | `/api/v1/media/:id` | 移入回收站 |
| POST | `/api/v1/media/:id/restore` | 从回收站恢复 |
| DELETE | `/api/v1/media/:id/permanent` | 永久删除 |
| GET | `/api/v1/media/trash` | 回收站分页 |
| DELETE | `/api/v1/media/trash` | 清空回收站 |
| GET | `/api/v1/media/unreferenced` | 未引用媒体分页 |
| DELETE | `/api/v1/media/unreferenced` | 全部未引用媒体移入回收站，返回 `deleted` |
| GET | `/api/v1/files/media/:id/:filename` | 原图/变体文件，支持 `?token=`、`?variant=`、`?thumb=` |

> 原 `PATCH /api/v1/media/:id` 已移除：关联只由正文推导，手工覆盖会在下次保存时被覆盖，属于歧义入口。

## 八、前端交互

### 8.1 媒体页（`web/src/routes/media/+page.svelte`）

- 三个视图：`媒体库` / `回收站 (N)` / `未引用 (N)`，角标数量进入页面即并行拉取。
- 点击卡片打开详情：大图预览（灯箱）、上传时间（回收站另有删除时间）、关联日记（可跳转到对应日期），
  底部为移入回收站 / 恢复 / 永久删除；删除后提示条提供“撤销”。
- 清空回收站与“全部移入回收站”均有确认面板。
- 空状态、加载骨架、错误提示按视图区分文案。

### 8.2 灯箱（`web/src/lib/stores/lightbox.ts` + `Lightbox.svelte`）

- 全局挂载（根布局），`openLightbox(string | LightboxImage | LightboxImage[], index)` 打开。
- 键盘：`Esc` 关闭、`←/→` 切图、`+/-/0` 缩放/复位。
- 缩放：滚轮以光标为锚点、双击在 1x/2.5x 间切换、双指捏合；范围 1x–4x。
- 放大后可鼠标或单指拖动平移，边界钳制；右下角控制条显示百分比。
- 移动端：单指横滑（>60px）切图，下拉（>100px）关闭，未达阈值回弹；`touch-action: none` 避免触发浏览器原生手势。
- 切图或关闭自动复位缩放与位移。

### 8.3 编辑器内预览

- 点击预览中的 `<img>` 使用 `currentSrc` 打开灯箱（自动带缩略图变体或原图）。
- 灯箱只展示单张：编辑器预览未聚合同篇日记的图片集合。

## 九、一致性与边界

| 场景 | 行为 |
| :--- | :--- |
| 只改心情/天气/标签 | 不触发关联同步，已有图片不丢 |
| 正文删除图片后保存 | 对应关联被删除，媒体进入“未引用” |
| 引用他人媒体 URL | 忽略，不建立关联 |
| 删除日记 | 关联级联删除，媒体文件保留（可能进入未引用） |
| 软删除媒体 | 关联保留，日记里显示为 404，可在回收站恢复 |
| 永久删除媒体 | 文件、行、变体缓存、关联一并清理 |
| 导入（文件/legacy 库） | 导入媒体时按 `diary` 字段写关联，日记导入时再按正文补齐 |
| 历史 `media.diary` | 迁移 v9 回填后不再读取，仅保留列 |

已知限制：

- 回收站保留期不可配置，固定 30 天。
- “全部移入回收站”无数量上限，一次请求处理该用户所有未引用媒体。
- 灯箱跨图片聚合只在外部传入图片数组时生效（目前媒体页与编辑器都是单张打开）。
